# 05 · 部署指南（Cloudflare Workers）

> 2026-08-31 起部署路线收束为 **Workers 静态资源 + 后台 API Worker**（原 Pages 双路线废弃）。
> 站点仍是纯静态产物（`pnpm build` → `dist/`），额外挂一个 Worker 处理 `/api/admin/*`（博客后台）。

## 前置

```bash
pnpm install
pnpm build          # 确认零报错，产物在 dist/
```

配置入口是根目录 `wrangler.jsonc`：`main = worker/index.ts`，`assets.directory = ./dist`，绑定名 `ASSETS`，自定义域 `blog.22331.top`。

## Secrets 配置（2026-08-31 已配好，重建时参考）

```bash
npx wrangler login
node scripts/gen-password.mjs                 # 输出管理密码 + SESSION_SECRET
npx wrangler secret put ADMIN_PASSWORD        # 管理密码原文
npx wrangler secret put SESSION_SECRET
npx wrangler secret put GITHUB_TOKEN          # 当前复用 gh 登录 token；建议换细粒度 PAT
```

> 密码用明文 secret + 恒定时间比对，**不用 PBKDF2/bcrypt**：Workers 免费版 10ms CPU
> 限制会击杀高迭代派生（线上表现为 error 1101）。secret 本身加密存于 Cloudflare，
> 单人站长 + 5 次失败锁 15 分钟已足够。GITHUB_TOKEN 建议：GitHub → Settings →
> Personal access tokens → Fine-grained，仅 marchtri-blog 仓库 Contents 读写。
>
> **警告：不要用 `wrangler secret delete`**（4.127 实测会把全部 secrets 与静态资产
> 绑定一起清空，导致 /admin/ 404 + 登录 500）。确需删除去 Cloudflare 控制台操作；
> 误删后用 `wrangler deploy` + 重新 put 全部 secrets 恢复。

## 发布

```bash
pnpm build && node scripts/deploy.mjs       # 等价于 npx wrangler deploy
```

## 自动发布（发文/push 后自动上线）

当前方案：**本机定时轮询**（Qoder 自动化，每 10 分钟）跑 `node scripts/auto-deploy-check.mjs`——
`git fetch` 比对 origin/main 与 `.deployed-sha`，有新 commit 就 `pnpm build && wrangler deploy`。
前提是本机保持开机且工作区干净；发文后台的 commit 由此在 10 分钟内上线。

可选升级（不依赖本机）：Cloudflare 控制台 → Workers → marchtri-blog → Settings → Builds →
Connect to Git（构建命令 `pnpm build`，输出 `dist`，`NODE_VERSION=22`）；或改用
GitHub Actions（需自建 `CLOUDFLARE_API_TOKEN`，OAuth token 无权限创建）。

## 本地开发

```bash
pnpm dev                        # 界面开发（无 /api，后台页会报请求失败，正常）
pnpm build && npx wrangler dev  # 联调后台：静态 + API 全真
```

联调时把 secret 值写进根目录 `.dev.vars`（格式 `KEY=value`，已被 .gitignore 屏蔽）。

## 博客后台

- 入口：`/admin/`（不进导航，直接访问）。功能与验收见 docs/03 P1-8。
- 开关：`config.ts → featureConfig.adminPanel`，置 false 后 /admin 返回 404（API 仍受密码保护）。

## 自定义域名

`wrangler.jsonc` 的 `routes` 已声明 `blog.22331.top` 为 custom_domain。
若该域名当前仍绑在旧 Pages 项目上：先在 Pages 项目里移除该域名，再 `wrangler deploy` 让 Worker 接管（有分钟级切换窗口）。

## 缓存策略

`public/_headers` 不变：带 hash 的 `_astro/*` `immutable`，HTML `no-cache`，字体 `max-age=31536000`（Workers 静态资产同样生效）。

## 常见问题

- **发文成功但站点没更新**：自动构建没接通，检查上文「让 push 自动上线」。
- **登录 429**：本地 isolate 内存计数锁 15 分钟，重启 `wrangler dev` 即清；线上属轻防护，可加 CF 速率规则。
- **构建内存不足 / 字体首包 / 天气接口 / 网易云空白**：同旧版，与部署方式无关。
